# 競馬予想AI (keiba-ai)

過去のレース結果から、同一レース内での各馬の相対的な強さを予測する
学習用の最小構成AIパイプラインです。データ収集(スクレイピング)・
特徴量エンジニアリング・LightGBM(LambdaMARTランキングモデル)・
Streamlit UI までを一通り含みます。

**⚠️ 重要な注意事項**
- 実サイトへのスクレイピング機能を含みますが、**対象サイトの利用規約(ToS)・
  robots.txt を必ず確認し、遵守できる範囲でのみ使用してください。** 本リポジトリの
  スクレイパーは既定でリクエスト間隔を空け、robots.txt が禁止しているURLへの
  アクセスは拒否しますが、これは免責にはなりません。利用は自己責任でお願いします。
- 予測結果は娯楽・研究目的のものであり、**賭け金や馬券購入の助言ではありません。**
- 同梱の合成データ (`synth_data.py`) は実在のレース・馬・騎手とは無関係の
  架空データです。ネットワークなしでパイプライン全体を試すために用意しています。
- `data/jra_results.csv`(収集済みの実データ)はリポジトリに含まれています。
  `models/` 以下(学習済みモデル・履歴)は `data/jra_results.csv` から数秒で
  再現できるため含めていません -- 詳しくは「自動化」の節を参照してください。

## 構成

```
src/keiba_ai/
  parser.py      # HTMLパース(純粋関数、ネットワーク非依存)
  scraper.py      # robots.txt尊重・レート制限付きのネットワーク層
  io.py           # CSV読み込み共通ヘルパー(ID列のゼロ落ち対策、下記参照)
  synth_data.py   # オフラインデモ/テスト用の合成レースデータ生成
  features.py     # 未来情報リークなしの特徴量エンジニアリング
  model.py        # LightGBMモデル(LambdaMARTランキング)の学習・保存・推論
  app.py          # Streamlit UI
scripts/
  generate_demo_data.py       # 合成データをCSVに書き出す
  scrape_jra_dirt_results.py  # 中央競馬(JRA10場)の実レース結果を収集
  update_dataset.py            # 既存データセットを差分更新して再学習(自動化用)
  predict_raceday.py           # 指定日の中央競馬レースをまとめて予測
  tune_hyperparams.py          # LightGBMハイパーパラメータのランダムサーチ
  train_model.py               # CSVからモデルを学習(--dirt-onlyでダート特化)
  predict_race.py              # 出馬表(CSV/URL)から1レース分を予測
tests/                          # pytest (parser/features/model/io/scraperのユニットテスト)
.github/workflows/
  weekly_update.yml             # 週次でupdate_dataset.pyを実行するGitHub Actions
```

## クイックスタート(合成データで一通り試す)

```bash
# 1. 合成レースデータを生成(実サイトへのアクセス不要)
python scripts/generate_demo_data.py --out data/demo_results.csv

# 2. モデルを学習
python scripts/train_model.py --data data/demo_results.csv \
    --model-out models/model.joblib --history-out models/history.csv

# 3. 出馬表CSV(過去成績と同じ列構成)を用意して予測
python scripts/predict_race.py --shutuba-csv data/sample_shutuba.csv \
    --model models/model.joblib --history models/history.csv
```

または Streamlit UI で:

```bash
streamlit run src/keiba_ai/app.py
```

サイドバーで「デモデータで試す」を選べば、その場でモデルを学習して
架空レースの予測結果を確認できます。`models/model_dirt.joblib` /
`models/history.csv` を用意済みなら「実データモデルを使う(学習済み)」
モードで、再学習なしに実データの予測をすぐ試せます(下記参照)。

## 実データを使う場合(中央競馬・ダート特化)

```bash
# 1. 中央競馬(JRA10場)のレース結果を収集(芝・ダート両方。理由は下記)
#    月ごとに分割して実行し、リクエスト間隔を空けるのを推奨(下の「収集のコツ」参照)
python scripts/scrape_jra_dirt_results.py \
    --start-date 20240101 --end-date 20240630 \
    --out data/jra_results.csv --max-races 2000 \
    --contact your-email@example.com

# 2. ダート限定でモデルを学習(馬/騎手の履歴特徴量には芝レースも活用しつつ、
#    学習対象の行だけダートレースに絞る)。model_dirt.joblib という名前で
#    保存すると、Streamlit の「実データモデルを使う」モードがそのまま拾う。
python scripts/train_model.py --data data/jra_results.csv --dirt-only \
    --model-out models/model_dirt.joblib --history-out models/history.csv

# 3. 予測(CLI、または streamlit run src/keiba_ai/app.py の
#    「実データモデルを使う(学習済み)」モードでも同じモデルを使える)
python scripts/predict_race.py --shutuba-csv data/sample_shutuba.csv \
    --model models/model_dirt.joblib --history models/history.csv
```

`scrape_jra_dirt_results.py` は `db.netkeiba.com` の日別レース一覧ページを
起点に、レースIDの2桁の場コード(01〜10)で中央競馬10場(札幌・函館・福島・
新潟・東京・中山・中京・京都・阪神・小倉)のみを抽出し、地方競馬(NAR)を
除外します。**芝レースもあえて収集・保存します**(馬/騎手の「全体的な実力」の
参考になり、出走間隔などの特徴量にも必要なため)。ダートへの特化は
`train_model.py --dirt-only` で学習対象の行を絞ることで行います。

### 収集のコツ(長期間のデータを集める場合)

一度に長い期間を `--start-date`/`--end-date` で指定すると、途中でネット
ワークエラーが起きた際に再実行がゼロからやり直しになりやすい(20レース
ごとにCSVへチェックポイント保存はされますが)ので、**月単位など小さい
期間に分けて複数回実行し、最後に結合する**方式を推奨します。同じ
`--cache-dir`(既定: `data/cache/netkeiba`)を使い回せば、取得済みページは
再フェッチされません。

```bash
for m in 01 02 03 04 05 06 07 08 09 10 11 12; do
  python scripts/scrape_jra_dirt_results.py \
      --start-date 2024${m}01 --end-date 2024${m}31 \
      --out data/chunks/jra_2024${m}.csv --max-races 400 \
      --contact your-email@example.com
done
python -c "
import pandas as pd, glob
df = pd.concat([pd.read_csv(f) for f in glob.glob('data/chunks/jra_2024*.csv')])
df.drop_duplicates(subset=['race_id','umaban']).to_csv('data/jra_results.csv', index=False)
"
```

学習データが少ない(数週間・数百レース程度)と、`horse_dirt_*` (馬のダート
限定成績)特徴量が十分に貯まらず精度が伸び悩みます。2年半強(ダート4,256
レース、2024年1月〜2026年8月16日)で学習した現在のランキングモデルでは、
**held-out precision@3が0.469**(モデルの予測上位3頭のうち約47%が実際に
3着以内)、**1・2・3着の3頭が全員、予測上位6頭以内に入る確率が0.373**
(37.3%)で、ランダムに3頭を選んだ場合の期待値(約0.2、フィールドサイズ
約15頭として3/15)を2倍以上上回っています。

⚠️ 実サイトへのアクセスを行うため、事前に対象サイトの利用規約を確認してください。

## モデルについて

- **目的関数**: LightGBMの `lambdarank`(LambdaMART)によるランキング学習。
  レースは「同じレース内の馬同士の相対順位」を当てる問題なので、各馬を
  独立に0/1分類するより、レース単位でグループ化してランキングを直接
  最適化する方が本来のタスクに合っています。目的変数は着順に基づく
  段階的な relevance ラベル(1着=3, 2着=2, 3着=1, それ以外=0)です。
  `model.predict()` の出力は**そのレース内でのみ意味を持つ相対スコア**
  (0〜1の確率ではありません)。`softmax_scores()` でレース内softmaxを
  取ると、フィールド内で合計100%になる「相対スコア(%)」として表示できます
  (的中確率そのものではない点に注意)。
- **較正済み複勝確率**: `KeibaModel.predict_top3_probability()` は、上記の
  生スコアを**アイソトニック回帰(isotonic regression)**で「実際に3着以内に
  入った過去の実績」に較正した、馬ごとに独立な確率です。学習時に
  held-outの検証データ(学習に使っていないレース)での実際の的中結果に
  基づいて較正するため、「このスコア帯の馬は、過去データでは実際に約◯%の
  確率で3着以内に入っている」という実績ベースの数字になります。
  `相対スコア(%)`と違い、レース内で合計100%にはなりません(3着以内に
  入るのは3頭なので、フィールド全体で足すとおおむね3.0前後になります)。
  Streamlit UIでは「3着以内率(推定,%)」列として両方のスコアを並べて
  表示しています。
- **評価指標**: `GroupShuffleSplit` でレース単位に分割し(同一レースの馬が
  学習/検証に分かれて跨がらないように)、held-outレースで指標を表示します。
  学習の最適化目標(`DEFAULT_PARAMS`の`eval_at`)は**6**に設定しており、
  「上位3頭の並び順を当てる」(`eval_at=3`)ではなく**「実際の1〜3着馬を
  上位6頭という広めの枠に収める」**ことを直接の目標にしています。これに
  合わせて指標も、`valid_ndcg@6`に加えて**`valid_recall@6`**(実際の
  1〜3着馬のうち何%が予測上位6頭に入っているか)と
  **`valid_all_top3_in_top6`**(1〜3着馬が全員、予測上位6頭に入る確率)
  を計算しています。`precision@3`(予測上位3頭のうち実際に3着以内だった
  割合)も比較用に引き続き算出しています。metricのキー名は`eval_at`の値
  から動的に決まるので、将来この値を変えても壊れません。
- 基本特徴量: 斤量・枠番・馬番・馬体重(増減)・年齢・距離・馬場状態・コース・
  性別に加え、**その馬/騎手のその時点までの成績を集計した「リークなし」特徴量**
  (出走数・勝率・複勝率・平均着順・前走からの間隔)を使用します。学習時は
  `groupby + cumsum` で各レースより前のデータのみから計算し、未来の結果が
  紛れ込まないようにしています。予測時(`build_prediction_frame`)には、その
  馬/騎手の**直近レースの結果まで織り込んだ**最新の統計を使います。
- **ダート特化特徴量**: 上記に加え、`horse_dirt_*` / `jockey_dirt_*`
  (ダートレースのみに絞った出走数・勝率・複勝率・平均着順)を持ちます。
  芝レースを挟んでも正しくスキップされ、その馬/騎手の直近の**ダートでの**
  実績のみを反映します(`tests/test_features.py` で検証)。芝適性とダート
  適性は必ずしも一致しないため、両者を区別して学習させています。
- **距離帯・コースバイアス特徴量**: `distance_band`(短距離≦1400m/マイル
  ≦1800m/長距離)のカテゴリと、`course_waku_bias_*`
  ((開催場, 芝/ダート, 距離帯, 枠番)の組み合わせごとの、リークなし展開勝率・
  複勝率・平均着順)を持ちます。これは特定の馬や騎手の実力とは独立に、
  「このコース・距離ではこの枠が構造的に有利/不利」といったコース固有の
  傾向を捉えるための特徴量です。
- **脚質(先行度合い)特徴量**: `horse_early_position_ratio_before` /
  `horse_dirt_early_position_ratio_before`。結果ページの「通過」列
  (コーナー通過順位)からその馬の歴代の先行度合い(0=常に先頭付近、
  1=常に後方)をリークなしで集計したものです。コースごとの脚質有利/不利は
  別途集計テーブルを作るのではなく、この連続値とコース系カテゴリ特徴量の
  交互作用としてLightGBMの木構造に学習させる設計です。
- **調教師(trainer)特徴量**: `trainer_runs_before` / `trainer_win_rate_before`
  / `trainer_top3_rate_before`(全体・ダート限定の両方)。jockey_*と全く同じ
  パターンで、調教師IDごとにリークなし展開集計しています。
- **馬×条件別のダート実績**: `horse_dirt_track_condition_*` /
  `horse_dirt_place_*` / `horse_dirt_distance_*`。`course_waku_bias_*`が
  「その条件でのフィールド全体の傾向」であるのに対し、こちらは**その馬自身
  が今回と同じ馬場状態・開催場所・距離のダート戦でどう走ってきたか**を
  リークなし展開集計したものです(いずれもダート戦に限定。`horse_dirt_*`
  同様、芝適性がそのまま転用できるとは限らないため)。学習時と同じ手法で
  `horse_dirt_distance_avg_rank_before`が特徴量重要度で上位10位以内に入る
  など、実際にモデルの予測に活用されていることを確認済みです。
  `track_condition`は出馬表発表直後は未確定(空欄)のことが多く、その場合は
  `popularity_numeric`/`odds_numeric`と同様に欠損(NaN)として扱われます。
- **追切評価(training_grade)**: netkeibaが公開している調教(追切)の
  A〜E評価をカテゴリ特徴量として使用します。生の調教タイムはnetkeiba
  プレミアム会員限定(1レースにつき3頭のみ無料プレビュー)で、しかも
  「注目馬だけ載る」という偏りがあるため使わず、全頭分が無料公開されて
  いる評価レターだけを`scripts/scrape_oikiri.py`で取得しています
  (`data/oikiri.csv`、race_id+horse_idキーで結合)。特徴量重要度でも
  上位5位以内に入るなど、実際に強く予測に寄与していることを確認済みです。
- **出走頭数(field_size)・過去の上がり3F平均**: 「事前に分かるデータで
  着順と相関のあるものは他にないか」を独立にSpearman相関で検証した結果
  追加した2つの特徴量です。`field_size`(出走頭数、頭数が多いほど3着以内
  が難しくなる)は相関が弱く(相関係数0.08、特徴量重要度でも下位)実際の
  寄与はごくわずかでしたが、`horse_avg_last_3f_before` /
  `horse_dirt_avg_last_3f_before`(その馬の過去の上がり3F=終い足の
  リークなし展開平均)は相関係数0.15と、平均着順ほど強くはないものの
  別の側面(瞬発力)を捉えており、特徴量重要度でも上位に入っています。
- **レースクラス(race_class)**: 未勝利・1勝クラス・オープン・G1〜G3などの
  格をレース名(`race_name`)から抽出したカテゴリ特徴量です。レース名自体は
  以前から取得していたのにCSVへ保存し忘れていたため、今回追加しました。
  同一レース内の平均着順とは(定義上ほぼフラットになるため)相関しません
  が、他の特徴量との交互作用(例:「未勝利では通用した勝率でも1勝クラス
  では通用しない」)を通じて効くタイプの特徴量です。特徴量以外は完全に
  同一の条件で有無を比較したところ、held-out precision@3が0.468→0.479
  (NDCG@3も0.465→0.479)と、単独でも明確にプラスに寄与することを
  確認しています。
- **血統(sire_id/damsire_id、試した結果は既定で無効)**: netkeibaの無料5代
  血統表ページ(`db.netkeiba.com/horse/ped/<horse_id>/`、調教タイムと違い
  ペイウォールなし)から父・母父を`scripts/scrape_pedigree.py`で全19,345頭分
  収集し、`data/pedigree.csv`に保存しています。「有名な種牡馬の産駒は多い
  ので、horse_id自体(ほぼ1行1カテゴリで無意味)と違って繰り返し出現する
  低〜中カーディナリティのカテゴリになるはず」という仮説でカテゴリ特徴量
  として試しましたが、**5種類のシードで比較した結果、有無以外は完全に
  同一条件でも一貫して精度が悪化しました**(NDCG@6が5シード中5シードで
  -0.005〜-0.017、precision@3が5シード中5シードで-0.001〜-0.008、
  `valid_all_top3_in_top6`が5シード中4シードで-0.008〜-0.028、シード42では
  0.3638→0.3732)。原因はおそらく、父・母父ともまだ数千種類の値があり、
  浅い木構造(`num_leaves=15`)の分割予算が、この疎なカテゴリの学習に
  割かれてしまい、その分`horse_dirt_*`などより効く既存特徴量への割り当てが
  減ること。そのため**カテゴリ特徴量としてはあえて`CATEGORICAL_FEATURE_COLUMNS`
  に含めていません**(`data/pedigree.csv`とtrain_model.py等の`--pedigree`
  結合処理自体は残してあるので、将来「生のIDではなく種牡馬ごとの集計勝率」
  のような別のエンコーディングを試す土台としては使えます)。
- **特徴量グループの組み合わせ探索**: 「今ある特徴量グループのうち、どの
  組み合わせが的中率を一番上げるか」を`scripts/feature_group_search.py`で
  検証しました。基本特徴量から出発し、毎ステップ残っている各グループを
  1つずつ追加してみて一番precision@3が上がるものを採用する貪欲法
  (forward selection)です。**3シード平均**での探索では、「馬/騎手の一般
  履歴」→「馬×条件別のダート実績」の2グループだけを追加した時点で、残り
  (ダート限定履歴・コースバイアス・脚質・上がり3F・調教師・追切評価・
  レースクラス)はどれも+0.0015の閾値を超えず探索が止まりました
  (precision@3 0.308→0.455→0.466)。しかしこれを**5シードでしっかり
  検証し直すと、話が変わります**: この「絞り込んだ2グループ」構成と、
  現在の既定(血統・市場系を除く全グループ)を正面から比較したところ、
  precision@3は5シード中4シードで既定側が上回り(既定0.457〜0.484 vs
  絞り込み0.452〜0.476)、NDCG@6・`valid_all_top3_in_top6`は**5シード全て
  で既定側が明確に上回りました**(例:`valid_all_top3_in_top6`はシード42で
  0.373 vs 0.344、シード2で0.365 vs 0.337)。つまり3シード平均の貪欲法は
  ノイズに惑わされて「打ち切りすぎ」ており、**個々のグループを追加した際の
  1回あたりの効果は小さくても(0.001〜0.01程度)、全部乗せた方が結果として
  一番的中率が高い**、というのが現時点の結論です。既定の特徴量構成
  (このセクションで説明している血統・市場系以外の全グループ)が、
  実際に検証した中では最良の組み合わせでした。この結果は「もっと網羅的な
  探索をすれば既定より良い組み合わせが見つかる可能性がゼロではない」ことも
  同時に示しています(貪欲法は全通りは試さないため)が、5シードでの
  再検証コストを考えると、現状はこれ以上の探索は費用対効果が低いと判断して
  います。
- **人気・オッズ特徴量(既定では無効)**: `popularity_numeric` / `odds_numeric`
  として実装済みですが、`train_model.py`は**既定でこれらを除外**します。
  理由は実験で判明した実務上の落とし穴です: 最終オッズ・人気は市場(＝他の
  馬券購入者全員の判断)を丸ごと特徴量に取り込むことになるため単体では
  圧倒的に強い予測力を持ちますが(下表参照)、レース数日前の出馬表では
  まだ確定しておらず("**"のようなプレースホルダ)、`predict_raceday.py`が
  想定する「直前ではないタイミングでの予測」ではほぼ全レースで欠損します。
  欠損すると学習時にこの特徴量に頼り切ったモデルの予測がほぼ一様になって
  しまうため、既定では除外し、`--include-market-features`を明示的に渡した
  ときだけ使う設計にしています。

  | 特徴量セット | held-out precision@3 | 1〜3着が上位6頭に全員入る確率 | 備考 |
  |---|---|---|---|
  | 人気・オッズ**あり** | 0.537 | 0.484 | 直前予測専用。オッズ確定前は使えない |
  | 人気・オッズ**なし(既定)** | 0.469 | 0.373 | いつでも使える。実運用のデフォルト |

- **ハイパーパラメータ**: `scripts/tune_hyperparams.py`
  (`learning_rate`/`num_leaves`/`min_data_in_leaf`/`feature_fraction`/
  `bagging_fraction`/`bagging_freq`/`lambda_l1`/`lambda_l2`の乱数サーチ)で
  見つけた値を`keiba_ai.model.DEFAULT_PARAMS`の既定値にしています。
  **⚠️ 探索結果の頑健性について**: 25組の候補を1回の分割(seed固定)だけで
  比較すると一番良く見えた組み合わせも、実際には**分割による誤差の範囲内**
  でした。上位2候補と旧パラメータ(eval_at=3向けにチューニングされていた
  もの)を5種類の異なるランダム分割で再学習して比較したところ、
  `valid_all_top3_in_top6`の平均は0.375〜0.380、標準偏差は0.008〜0.015と、
  候補間の差(0.002〜0.004)より分割ごとのブレの方が大きく、**どれが
  「真に最適」かは統計的に区別できませんでした**。現在の既定値はこの
  検証における平均順位が良かったものを採用していますが、大きな改善という
  よりは「同程度に良い候補の中の一つ」という位置づけです。
- 1年分の実データで学習したところ、上記のダート特化・コースバイアス・
  脚質・調教師の各特徴量群はいずれも特徴量重要度の上位〜中位に入り、実際に
  予測に寄与していることを確認しました。
- **⚠️ 修正した重大なバグ**: 騎手・調教師IDはゼロ埋め("01209"など)された
  文字列ですが、`pd.read_csv`はこれを全桁数字の列とみなして`int64`型に
  自動推論し、先頭のゼロを黙って落とします(`"01209"` → `1209`)。保存前の
  スクレイピング直後のデータでは文字列のまま保持されるため、この型不一致で
  騎手・調教師の統計がほぼ全件マッチせずNaNになっていました(CSV往復した
  データ同士を比較していたテスト・デモでは症状が出ず、`predict_raceday.py`
  でライブ出馬表と結合して初めて発覚)。`keiba_ai.io.read_race_csv`で
  ID列を明示的に文字列型として読み込むよう修正し、全CSV読み込み箇所を
  これに統一しました(`tests/test_io.py`で回帰テスト済み)。

## 馬券戦略の検証(実払戻データでのバックテスト)

held-outレース(モデルが学習に使っていない852レース)に対して、netkeibaの
実際の払戻データを使い、複数の馬券戦略・絞り込み条件を検証しています。

- **単純な戦略は軒並み赤字**(`scripts/backtest_betting_strategies.py`):
  予測上位馬をそのまま単勝・複勝・ワイドボックス・馬連ボックス・3連複ボックス・
  1頭軸流し(3連複/3連単)で機械的に買った場合、**全8種類の買い方でROIが
  100%を下回りました**(57.9%〜78.6%)。原因はJRAの控除率(単勝・複勝は
  約20%、馬連・ワイドは約22.5%、3連複・3連単は約27.5〜30%)で、モデルの
  精度がどれだけ良くても、この控除分を上回る優位性がなければ長期的には
  必ず負けます。
- **オッズに対する優位性(EV)は見つからず**(`scripts/ev_win_backtest.py`):
  「較正済み勝率×最終オッズ−1」が正(市場より割安)の馬だけに絞って単勝を
  買っても、EVの閾値をどう変えてもROIはほぼ横ばい(75〜79%)でした。
  つまりこのモデルの予測確率は、既に市場(オッズ)が織り込んでいる情報を
  大きく超える優位性を持っていません。
- **「自信度が高いレースに絞る」効果を検証**(`scripts/confidence_filter_backtest.py`、
  ユーザーからの提案で追加): 予測1位馬自身の較正済み3着以内確率
  (`top3_probability`)でレースを分位に分け、「自信度が高いレースだけに
  絞ると的中率・回収率が上がるか」を検証しました。

  | 自信度(1位馬のtop3_probability) | レース数 | 3着以内的中率 | 単勝ROI | 複勝ROI |
  |---|---|---|---|---|
  | 全体(絞り込みなし) | 852 | 55.9% | 75.0% | 78.6% |
  | 下位グループ(0.16〜0.41) | 256 | 48.4% | 75.7% | 75.7% |
  | 上位グループ(0.58〜1.00) | 191 | 68.1% | 78.2% | 86.6% |
  | 最上位(上位約8%、0.67以上) | 66 | **77.3%** | 76.1% | **94.1%** |

  **的中率は自信度と一緒に明確に上がります**(相関係数0.16、最上位グループ
  では77.3%まで上昇)。しかし**回収率はそれに比例して上がりません**。理由は
  単純で、モデルが自信を持つ馬は市場(オッズ)からも人気になりやすく、
  的中しやすい分オッズが低く(＝1回あたりの払戻が小さく)なるため、
  的中率の上昇分がオッズの低下でほぼ相殺されるからです。最も自信度が高い
  上位約8%のレースに絞った複勝だけは94.1%まで改善し損失が小さくなります
  が、それでも黒字化はしませんでした(このグループはn=66と少なく、
  誤差の余地も相応にあります)。
- **レースクラス別の検証**(`scripts/race_class_backtest.py`、ユーザーからの
  提案で追加): 「注目度の高いレース(G1など)は分析好きなファンが大勢
  予想するので市場が効率的だが、地味なレース(未勝利・1勝クラス)は研究
  している人が少なく市場の見積もりが甘いのでは」という仮説を検証しました。

  | レースクラス | レース数 | 3着以内的中率 | 単勝ROI | 複勝ROI |
  |---|---|---|---|---|
  | 未勝利+1勝クラス | 591 | **58.4%** | **78.3%** | **81.1%** |
  | それ以外(新馬・2勝クラス以上) | 261 | 50.2% | 67.4% | 73.1% |
  | 全体 | 852 | 55.9% | 75.0% | 78.6% |

  **仮説通り、未勝利・1勝クラスに絞ると的中率・回収率とも全体平均より
  明確に良くなりました**(単勝ROIで+10.9pt、複勝ROIで+8.0pt)。件数も
  591レースとサンプルとして十分な規模です。ここまでの検証(自信度による
  絞り込み・EVフィルタリング)の中で、控除率の壁に一番迫れた結果です。
  なお、レースクラスをG1〜3勝クラスまで細かく分けた表では一部
  (G1が2レース、G3が9レースなど)極端に少ないクラスもあり、そこでの
  数字は誤差が大きく信頼できません。あくまで「未勝利+1勝クラス vs
  それ以外」という粗いくくりの比較が妥当な結果です。
- **レースクラス×自信度の重ね合わせ**: 上記2つの絞り込みを掛け合わせたら
  さらに近づけないか、を確認しました。「未勝利+1勝クラス」に絞った591
  レースの中で、さらに予測1位馬の自信度(top3_probability)が高い順に
  絞り込むと:

  | 絞り込み(未勝利+1勝クラスの中で) | レース数 | 的中率 | 単勝ROI | 複勝ROI |
  |---|---|---|---|---|
  | 上位80%(自信度0.583以上) | 124 | 71.0% | 81.5% | 90.2% |
  | 上位5%(自信度0.674以上) | 37 | 83.8% | 77.6% | **98.6%** |

  2つの絞り込みを重ねると単独より近づき、最も絞った条件(n=37)では
  複勝ROIが**98.6%とほぼ収支トントンの水準**まで来ました。ただし
  n=37は誤差の余地が大きく、これを「勝てる」と断言するには追加検証が
  必要と判断し、実際に複数シードで再検証しました(次項)。
- **複数シードでの頑健性チェック**(`scripts/robustness_class_confidence_backtest.py`):
  上記の単一split(seed=42)の結果が本物の効果か単なる運かを、6種類の
  異なる乱数シードでモデルを再学習・再検証して確認しました(各シードで
  train/valid分割が変わるので、実質的に異なる852レースのholdoutセットで
  同じ条件を6回試したことになります)。

  | 絞り込み条件 | 平均複勝ROI | 標準偏差 | 範囲(6シード) |
  |---|---|---|---|
  | 絞り込みなし(852レース) | 81.0% | 1.7pt | 79.2%〜84.0% |
  | 未勝利+1勝クラスのみ | **83.4%** | **1.2pt** | 81.8%〜85.4% |
  | ↑さらに自信度上位5% | 89.5% | 6.4pt | 83.9%〜**103.1%** |

  **「未勝利+1勝クラスに絞る」効果は本物でした**: 6シード全てで絞り込み
  なしを上回り(平均+2.4pt)、標準偏差もわずか1.2ptと非常に安定しています。
  一方、**さらに自信度で絞り込む効果は再現性に乏しいことが判明しました**。
  平均ROIは89.5%とさらに改善しましたが、標準偏差が6.4ptと5倍以上に
  跳ね上がり、シードによっては83.9%(むしろ悪化)から103.1%(黒字!)
  まで大きくばらつきます。元の単一split(seed=42)で見た98.6%は、この
  ばらつきの範囲内では「やや良い方の結果」であり、安定して再現できる
  水準ではありませんでした(絞り込むほどレース数が減る=n=30〜50程度
  なので、統計的なブレが大きくなるのは自然な帰結です)。
- **本命-穴馬バイアス(favorite-longshot bias)の検証**
  (`scripts/favorite_longshot_backtest.py`、ユーザーからの提案で追加):
  競馬の実証研究でよく知られる「人気薄(穴馬)は実際の勝率以上に過大評価
  されて買われ、本命(人気馬)は逆に過小評価されがち」という現象
  (Thaler & Ziemba 1988ほか)を、モデル自身の予測に当てはめて検証しました。
  モデルの予測1位馬が**市場の実際の人気(オッズ順位)でも1番人気だった
  場合**と、**モデルは推しているが市場的には人気薄だった場合**とで、
  回収率に差が出るかを見ています(6シード合計・held-out全レース分を
  プールして集計、nが大きいぶん信頼性も高いです)。

  | モデル1位予想の市場人気 | 全体でのレース数 | 複勝ROI(標準偏差) | 未勝利+1勝クラスでのレース数 | 複勝ROI(標準偏差) |
  |---|---|---|---|---|
  | 1番人気(市場の本命と一致) | 2,673 | 86.8%(3.6pt) | 1,947 | **88.3%(2.3pt)** |
  | 2番人気 | 1,150 | 77.3%(2.8pt) | 815 | 78.3%(2.1pt) |
  | 3番人気 | 517 | 70.7%(7.0pt) | 368 | 76.4%(5.5pt) |
  | 4番人気以下 | 750 | 75.7%(10.7pt) | 481 | 80.1%(9.5pt) |

  **バイアスの存在がはっきり確認できました**: モデルの1位予想が市場の
  本命(1番人気)と一致するときの複勝ROIが、全レースで86.8%、未勝利・
  1勝クラスに絞ると**88.3%**と、他の人気帯より頭一つ抜けて高く、しかも
  標準偏差2.3pt・n=1,947と、今回の一連の検証の中で最も大きく・最も
  安定したサンプルです。逆にモデルが市場の人気薄を推す(3番人気以下)
  ケースは、標準偏差も大きく(5.5〜9.5pt)、ROIも低めで不安定でした。
  「未勝利+1勝クラス」×「予測1位が市場の本命とも一致」を重ねた88.3%は、
  今回の検証全体で最も信頼できる好条件です。
- **不一致レースでは、モデルの1位予想自体が一番弱い**
  (`scripts/disagreement_rank_backtest.py`、ユーザーからの提案で追加):
  上と逆に、モデルの予測1位が市場の本命と**一致しない**レースだけに
  絞り、指数1〜6位それぞれと、市場の実際の1番人気(モデルが何位に
  付けていたかは問わない)それぞれに単勝1,000円・複勝2,000円を賭けた
  場合のROIを比較しました(3シードプール、n=1,958)。

  | 賭けた対象 | 単勝ROI | 複勝ROI |
  |---|---|---|
  | 指数1位(モデルの一押し) | **66.6%** | **76.1%** |
  | 指数2位 | 79.8% | 81.1% |
  | 指数3位 | 75.3% | 79.6% |
  | 指数4位 | 73.1% | 74.4% |
  | 指数5位 | 81.7% | 81.8% |
  | 指数6位 | 88.6% | 80.8% |
  | 市場の実際の1番人気 | 81.2% | **85.0%** |

  **モデルと市場が食い違うレースでは、モデルの1位予想こそが一番成績が
  悪い**という、直感に反する結果になりました(単勝66.6%・複勝76.1%は
  表の中で最下位)。指数2〜6位はどれも指数1位よりはっきり良く、中でも
  **市場の実際の1番人気を素直に買う方が、モデルの1位予想を買うより
  ずっと良い**(複勝で+8.9pt)という結果です。指数2〜6位の間には
  はっきりした順位付けは見られず(単一シードでは指数5位の単勝が
  101.9%と突出しましたが、3シードに増やすと81.7%まで落ち着き、
  単発のブレだったと判明しました)、「不一致のときは2〜6位のどれかに
  乗り換えるべき」とまでは言えませんが、**「不一致のときにモデルの
  1位予想をそのまま信じるのは悪手」ということはデータではっきり
  裏付けられました**。理由として考えられるのは、モデルが市場と
  食い違う=モデルが何らかのノイズ(直近の巻き返し期待、特定の脚質
  への過剰反応など)を拾って判断がブレているケースが多く、それなら
  素直に市場の集合知(実際の1番人気)に従った方が無難、ということ
  でしょう。実務的には、**「予測1位が市場の本命と一致しないレースは
  そもそも見送るか、見送らないなら市場の本命を買う」**のが、今回の
  データからは最も理にかなった対応です。
- **最良セグメントをさらに掘り下げ**(`scripts/best_segment_backtest.py`):
  「未勝利+1勝クラス」×「予測1位=市場1番人気」(n=1,947)の中で、単勝・
  複勝・ワイドBOX・馬連BOXを比較したところ、**複勝(88.3%)が最も良く**、
  単勝(80.1%)・ワイドBOX(75.9%)・馬連BOX(72.8%)はいずれも劣りました
  (このセグメントは「ほぼ確実に馬券に絡む本命」を捉えているので、1着を
  厳密に当てる単勝よりも3着以内でよい複勝の方が相性が良いということ)。
  さらにこのセグメントの中で、自信度(top3_probability)が高い順に段階的に
  絞り込むと:

  | セグメント内の絞り込み | レース数 | 複勝ROI | 標準偏差 |
  |---|---|---|---|
  | 絞り込みなし(セグメント全体) | 1,947 | 88.3% | 2.3pt |
  | 上位70% | 604 | 92.3% | 6.3pt |
  | 上位20% | 370 | 94.0% | 4.5pt |
  | 上位10% | 218 | 95.7% | 4.7pt |
  | 上位5% | 105 | **96.4%** | 6.2pt |

  自信度で絞り込むほど階段状に着実にROIが上がっており(88.3%→96.4%)、
  単発の跳ね上がりではなく一貫した傾向なので、これは単なる誤差ではなく
  本物の効果だと考えられます。ただし**最も絞った条件(n=105)でも96.4%と、
  黒字(100%超え)まであと一歩届きませんでした**。件数もこれ以上絞ると
  数十件規模になり、以前の自信度単体フィルタ(n=37, 標準偏差6.4pt)と
  同じ統計的な壁にぶつかるため、これ以上の深掘りは費用対効果が低いと
  判断しています。
- **開催場(コース)による違い -- 当初はついに黒字化するシードが出現**
  (`scripts/extra_dimensions_backtest.py`、ユーザーからの提案で追加。
  ※この結果は次の項目でデータを増やして再検証した結果、効果が縮小
  することが分かりました -- 詳細は次項):
  「未勝利+1勝クラス×予測1位=市場1番人気」セグメント(n=1,947)を
  開催場別に見ると、**札幌・函館・福島・新潟(いわゆる地方色の強い、
  開催規模が小さい4場)が96.9〜99.4%と、東京・中山・京都・阪神などの
  主要場(82.5〜88.4%)よりはっきり良い**ことが分かりました。レース
  クラスの時と同じ「注目度が低い=市場が非効率になりやすい」パターンが、
  開催場という別の軸でも再現された形です。この4場だけに絞ると:

  | 絞り込み | レース数 | 複勝ROI |
  |---|---|---|
  | 未勝利+1勝クラス×1番人気(全開催場) | 1,947 | 88.3% |
  | ↑さらに札幌・函館・福島・新潟に限定 | 476 | **98.3%** |

  6シードそれぞれで見ると 94.5% / 95.7% / **107.8%** / 92.6% /
  **104.8%** / 97.0% となり、**6シード中2シードで実際に100%を
  超えました**。範囲も92.6〜107.8%とこれまでの過絞り込み系の結果
  (自信度単体、標準偏差6pt超)より収まりが良く、n=66〜91/シードと
  極端に小さいわけでもありません。さらにこの「地方4場の方が良い」
  傾向は、レースクラス・自信度で一切絞り込んでいない全レースでも
  同じ方向に出ています(地方4場87.8% vs 主要6場79.1%、n=1,143 vs
  3,969)ので、このセグメント固有の偶然ではなく、独立した構造的な
  効果である可能性が高いです。今回の一連の検証の中で、初めて
  「勝てた」シードが複数出た、最も有望な組み合わせです。
- **データを2023年分追加して再検証 -- 効果は縮小(重要な教訓)**:
  上記の「地方4場」効果が本物か、単に学習データ(当時2.6年分・held-out
  852レース/シード)が少なかったことによる過大評価だったのかを確認する
  ため、2023年通年のデータを追加収集して(ダートレース4,256→5,908、
  +39%)、held-outレース数を852→1,182/シードに増やした上で同じ検証を
  やり直しました。結果:

  | | 追加前(2.6年分) | 追加後(3.6年分) |
  |---|---|---|
  | 地方4場(未勝利+1勝クラス×1番人気内) | 98.3%(n=476) | 90.3%(n=647) |
  | 6シードの範囲 | 92.6%〜**107.8%**(2シードが黒字) | 82.3%〜93.9%
    (黒字シードなし) |
  | 地方4場 vs 主要6場(絞り込みなし全体) | 87.8% vs 79.1% | 81.2% vs
    80.6%(ほぼ差なし) |

  **「地方4場が明確に良い」という効果は、データを増やすと大きく縮小
  しました**。特に絞り込みなし全体で見た地方4場 vs 主要6場の差は、
  当初の+8.7ptからほぼ0(+0.6pt)まで縮み、これはノイズと区別が
  つきません。セグメント内(未勝利+1勝クラス×1番人気)でも+13.3ptから
  +4.2ptへと縮小し、黒字シードも消えました。**当初の98.3%・2シード
  黒字という結果は、相対的に小さいサンプル(n=66〜91/シード)による
  過大評価だった可能性が高い**、というのが正直な結論です。これは
  この一連の検証全体にとって重要な教訓でもあります: 絞り込みを重ねる
  ほどサンプルは小さくなり、見かけの効果は本物より大きく出やすいので、
  可能な限り大きなサンプルで検証することが欠かせません。なお、
  縮小したとはいえ+4.2ptの差はまだ残っており、方向性自体(地方場の方が
  やや良い)は完全に否定されたわけではありません。
- **開催場ごとにパラメータを最適化すると逆効果になった**
  (`scripts/venue_specific_backtest.py`、ユーザーからの提案で追加):
  「地方4場」の効果は縮小したものの完全には消えなかったので、「そもそも
  開催場ごとに条件(自信度の閾値)を個別最適化したら、統一条件より
  良くなるのでは」を検証しました。過学習を避けるため、6シードを
  TUNE用3シードとTEST用3シードに分割: TUNE側だけを見て開催場ごとに
  最良の閾値を選び(例: 中京→0.6, 阪神→0.5, 京都→0.4 ...)、その閾値を
  **見たことのないTEST側**に適用して初めて効果を測る、という手順です。

  結果、**TUNE側では良く見えた閾値の多くが、TEST側では大きく崩れました**
  (例: 中京はTUNE上101.9%→TEST 81.9%、小倉は108.3%→79.4%、阪神は
  90.0%→79.0%)。逆にTUNE→TESTで良くなった開催場(中山、福島)もありま
  したが、これも同じ理由(小サンプルでの偶然)による逆方向のブレと
  考えるのが自然です。全開催場共通の単一閾値(0.5)と、開催場ごとに
  個別最適化した閾値を同じTESTデータ・同程度の賭け数で比べたところ、
  **単一閾値の方が明確に上回りました**(統一閾値83.1% vs 開催場別
  チューニング81.6%)。つまり**開催場ごとの個別最適化は、今のデータ量
  (1開催場あたり年間数百レース程度)では効果がないどころか、単純な
  統一ルールより悪化する**という結論です。原因は明快で、開催場を10分割
  するとさらにサンプルが小さくなり、地方4場の効果検証で学んだ「小サン
  プルでの過学習」がより強く出るためです。モデル自体を開催場ごとに
  再学習する案も同じ理由で見送りが妥当と判断しています。
- **2022年分を追加(4.6年分に拡大)して再検証 -- 阪神で気になる結果**:
  ユーザーの提案で2022年通年(ダート994レース)を追加収集し、学習データを
  2022年1月〜2026年8月の約4.6年分(ダート6,931レース)に拡大した上で、
  同じTUNE/TEST検証をやり直しました。結果、**多くの開催場でTUNE→TESTの
  乱高下が収まりました**(例: 小倉85.6%→85.1%、札幌87.5%→88.1%、
  阪神107.2%→105.2%と、ほぼ一致)。ただし全開催場をプールした総合比較
  では、単一のグローバル閾値(0.6)が91.0%(n=483)と、開催場別
  チューニング83.9%(n=1,643)を上回りました -- **「10開催場すべてを
  個別最適化する」という当初の狙い自体は、依然として単純な統一ルールに
  勝てていません**(閾値0.6を選ばなかった開催場が平均を押し下げている
  ため)。

  一方で、**阪神×自信度0.6以上という組み合わせだけは特筆に値します**。
  6シード全てで複勝ROIが96.5%〜123.9%という狭い範囲に収まり(6シード
  プールで106.1%, n=197)、**今回の一連の検証全体で最も一貫して黒字圏に
  近い(というより実際に黒字の)結果**でした。ただし、10開催場×5段階の
  閾値=50通りの組み合わせを試した中から一番良く見えるものを選んでいる
  ため(多重比較)、純粋な偶然でもこの程度の「当たり」は一定確率で
  出ること自体は否定できません。実運用に足る自信を持つには、今後
  新しく集まるデータ(このセグメントを一切見ずに追加された、真に
  独立したholdout)で再現するかを確かめる必要があります。
- **総合的な結論**: 一連の絞り込み検証を通じて分かった、再現性のある
  効果は主に3つです(データを増やして裏取りできたもののみ)。
  (1) レースクラスを未勝利・1勝クラスに絞る(複勝ROI +2〜3pt、標準偏差
  1.2ptと安定)、(2) モデルの予測1位が市場の本命(1番人気)とも一致する
  レースに絞る(複勝ROI 88.3%、標準偏差2.3pt)、(3) さらにその中で
  自信度上位に絞る(複勝ROI 96.4%、n=105、ただし小サンプル)。
  開催場(札幌・函館・福島・新潟)による絞り込みも方向性としては残り
  ますが(+4.2pt)、当初見えていたほど大きくはなく、データを増やす
  ことで見かけの効果が縮んだ好例として記録しています。逆に、自信度
  単体・市場の人気薄狙いはいずれも再現性に乏しいことも分かりました。
  **絞り込みなしの81.0%から、レースクラス→本命一致→自信度と重ねる
  ことで96.4%まで着実に差を縮められましたが、100%(黒字)は最終的に
  超えられませんでした。** JRAの控除率という壁は今回の検証範囲では
  崩せませんでしたが、「どの絞り込みが本物で、どれがサンプル数不足に
  よる幻だったか」を大きなデータで裏取りできたことが、この一連の
  検証で最も価値のある成果です。
- **予測の「形」と買い方の相性**(`scripts/bet_type_recommender_backtest.py`、
  ユーザーからの提案で追加): 「どの買い方が良いか」は今まで平均で比較
  してきましたが、**レースごとの予測の形(上位6頭の確率がどれだけ
  バラついているか)によって、相性の良い買い方が変わるか**を検証しました。
  6シードプールで8,317レース分、上位6頭の較正済み3着以内確率から
  `top1_prob`(1位の自信度)・`gap12`(1位と2位の差)・`spread6`(上位6頭の
  ばらつき=標準偏差)の3指標を計算し、8種類の買い方それぞれのROIとの
  Spearman相関、および指標を4分位に分けたときの最良の買い方を調べました。

  結果: **`spread6`(上位6頭のばらつき)が、単純な単勝・複勝以外の
  買い方すべてと中程度の正の相関を持ちます**(umaren_box3で0.178、
  fuku3_nagashiで0.176)。つまり**上位陣の実力差がはっきりしている
  レースほど、組み合わせ買い(ワイドBOX・馬連BOX・3連複流し等)の
  成績が(相対的に)良くなります**。実際、`spread6`が上位25%のレース
  では umaren_box3=86%・wide_box3=84% と複勝(89%)にかなり近づくのに
  対し、下位25%のレースでは umaren_box3=63%・wide_box3=71% と複勝
  (76%)から大きく離されます。ただし**複勝は12個の分位バケツ全て
  (3指標×4分位)で例外なく最良の買い方**でした -- 「形によって一番
  良い買い方が入れ替わる」わけではなく、「複勝が常に最良、ただし
  形がはっきりしたレースでは組み合わせ買いとの差が縮まる」という
  結論です。この知見を`predict_raceday.py`の出力に組み込み、レースご
  とに参考情報として表示するようにしました(下記「予想結果の見方」
  参照)。

## 自動化(実運用に向けて)

```bash
# 差分更新: 前回の最終日の翌日〜昨日までを自動スクレイピングし、
# データセットに追記して再学習まで一括で行う
python scripts/update_dataset.py \
    --data data/jra_results.csv \
    --model-out models/model_dirt.joblib --history-out models/history.csv \
    --contact your-email@example.com

# 開催日一括予測: 指定日の中央競馬(ダート)レースを自動検出し、
# 出馬表を取得してレースごとに予測をまとめて表示
python scripts/predict_raceday.py --date 20250111 --dirt-only \
    --model models/model_dirt.joblib --history models/history.csv \
    --contact your-email@example.com --out reports/20250111.csv
```

- `update_dataset.py` は `--data` の最終日を見て次の日から自動的に日付範囲を
  計算するので、日付を手計算する必要はありません。データが存在しない状態
  (初回)では `--start-date` を渡してください。
- `predict_raceday.py` は `race.netkeiba.com` のライブ開催スケジュール
  (レース結果データベースではなく、まだ結果の出ていない開催カード)から
  その日のレースを自動検出します。レース開催の数日前〜当日に、開催者が
  カードを公開してから使えます(それより先の日付は未公開のため空になります)。

### GitHub Actions での自動更新

`.github/workflows/weekly_update.yml` が毎週月曜18:00 UTC(火曜3:00 JST、
週末のJRA開催が一通り終わった後)に `update_dataset.py` を実行します。

- 使うには、リポジトリの Settings → Secrets and variables → Actions →
  Variables で **`SCRAPER_CONTACT_EMAIL`**(スクレイパーのUser-Agentに
  埋め込む連絡先)を設定してください。
- 更新された `data/jra_results.csv` は自動的にコミット・pushされます。
- `models/model_dirt.joblib` / `models/history.csv` はリポジトリにコミット
  せず(`data/jra_results.csv` から数秒で再現できるため)、ワークフローの
  実行結果(Artifacts)からダウンロードする形にしています。
- 手動実行(`workflow_dispatch`)にも対応しているので、Actionsタブから
  いつでも即座にトリガーできます。

⚠️ 定期的な自動スクレイピングになるため、有効化する前に対象サイトの利用規約を
再度ご確認ください。

## Streamlit UIのモード

- **デモデータで試す**: 合成データでその場学習・予測(ネットワーク不要)。
- **実データモデルを使う(学習済み)**: `models/model_dirt.joblib` /
  `models/history.csv` を読み込み、再学習せずに実データでの予測を確認。
  履歴データ内のダートレースを選んで予測 vs 実際の着順を見比べられます。
  事前に上記の収集・学習コマンドを実行しておく必要があります。
- **今日・明日のレースを予想**: `predict_raceday.py`と同じ仕組みをUIに統合し、
  コマンドラインを使わずにこれから開催されるレースを予想できるモード。
  日付(今日/明日ボタンまたはカレンダー)を選ぶと、その日の中央競馬の
  開催カードを`race.netkeiba.com`から取得し、レースごとに予想結果を表示する。
  出馬表がまだ発表されていない日付は空振りになる(通常、開催の数日前に発表)。
- **CSVをアップロード**: 自前の過去成績CSV・出馬表CSVで学習・予測。
- **URLから取得(スクレイピング)**: netkeibaのURLをその場で取得して学習・予測
  (少数URLでは精度は出ません。デモ用途)。

## テスト

```bash
pytest tests/ -v
```

`tests/fixtures/` の静的HTMLを使って `parser.py`/`scraper.py`(開催日一覧の
場ごとグルーピング含む)を検証し、`features.py` は手作りの小さなデータ
セットでリークが起きていないこと(ダート限定履歴・コースバイアス・脚質・
調教師の各特徴量について)を、`model.py` は合成データで学習したモデルが
ランダムな3頭選択(precision@3 ≈ 0.3)を明確に上回ることを確認します。
`test_io.py` は、ゼロ埋めID列がCSV往復で壊れないことを回帰テストします。
